## Задание 1  
### Распределённое вычисление среднего значения и стандартного отклонения

**Описание:**
- На процессе `rank = 0` создаётся массив случайных чисел размером `N = 10^6`.
- Массив распределяется между процессами с помощью `MPI_Scatterv`.
- Каждый процесс вычисляет локальную сумму и сумму квадратов.
- Итоговые значения собираются с помощью `MPI_Reduce`.

**Используемые функции MPI:**
- `MPI_Scatterv`
- `MPI_Reduce`
- `MPI_Wtime`

**Результаты (пример):**

| Процессы | Время (с) |
|----------|-----------|
| 2        | 0.0377    |
| 4        | 0.1060    |
| 8        | 0.1325    |

Среднее значение: `0.499769`  
Стандартное отклонение: `0.288837`

Вывод:

Во всех запусках среднее значение и стандартное отклонение совпадают, что подтверждает корректность распределённых вычислений. При увеличении числа процессов время выполнения возрастает. Это связано с тем, что при фиксированном размере массива накладные расходы на передачу данных и синхронизацию процессов превышают выигрыш от параллельных вычислений, особенно в среде Google Colab.

## Задание 2  
### Распределённое решение системы линейных уравнений методом Гаусса

**Описание:**
- Процесс `rank = 0` инициализирует матрицу коэффициентов `A` и вектор `b`.
- Строки матрицы распределяются между процессами с помощью `MPI_Scatter`.
- На каждом шаге прямого хода ведущая строка передаётся с помощью `MPI_Bcast`.
- Обратный ход выполняется на процессе `rank = 0`.

**Используемые функции MPI:**
- `MPI_Scatter`
- `MPI_Bcast`
- `MPI_Gather`

**Решение системы:**
x[0] = 1

x[1] = 3.5

x[2] = -1.5

x[3] = 0.5



Вывод:

Полученное решение системы линейных уравнений одинаково для всех запусков, что подтверждает корректность параллельной реализации метода Гаусса. При увеличении количества процессов наблюдается рост времени выполнения, так как размер матрицы мал и время обмена данными между процессами превышает время собственных вычислений.

## Задание 3  
### Параллельный анализ графов (алгоритм Флойда–Уоршелла)

**Описание:**
- Процесс `rank = 0` создаёт матрицу смежности графа.
- Строки матрицы распределяются с помощью `MPI_Scatter`.
- На каждой итерации алгоритма используется `MPI_Allgather` для синхронизации данных.
- После завершения итераций выводится матрица кратчайших путей.

**Используемые функции MPI:**
- `MPI_Scatter`
- `MPI_Allgather`

**Матрица кратчайших путей:**

0 3 5 6

5 0 2 3

3 6 0 1

2 5 7 0


Вывод:

В ходе экспериментов установлено, что эффективность параллельных MPI-программ существенно зависит от размера задачи и стоимости коммуникаций. При малых объёмах данных увеличение числа процессов не приводит к ускорению, а наоборот может ухудшать производительность. Реальный выигрыш от параллелизма достигается при работе с большими данными и на вычислительных кластерах с быстрыми каналами связи.

## Компиляция и запуск

### Установка MPI:
```bash
apt-get update -y
apt-get install -y openmpi-bin libopenmpi-dev

mpic++ program.cpp -o program
mpic++ gauss_mpi.cpp -o gauss_mpi
mpic++ floyd_mpi.cpp -o floyd_mpi

mpirun --allow-run-as-root --oversubscribe -np 4 ./program
mpirun --allow-run-as-root --oversubscribe -np 4 ./gauss_mpi
mpirun --allow-run-as-root --oversubscribe -np 4 ./floyd_mpi

## Анализ производительности

Эксперименты показали, что при малых размерах входных данных увеличение числа процессов приводит к росту времени выполнения из-за накладных расходов на обмен сообщениями. Эффективность параллельных алгоритмов проявляется при увеличении размера задач.
